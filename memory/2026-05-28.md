# 2026-05-28

- Started new `cygnus-bike` project for CYC X1 Pro Gen4 Bluetooth work.
- Read-only probe of example motor `CYCMOTOR` at `<CYCMOTOR_ADDRESS>` found GAP/GATT plus Nordic UART Service `6e400001-b5a3-f393-e0a9-e50e24dcca9e`.
- Nordic UART handles: write characteristic `6e400002...` value handle `0x000d`; notify characteristic `6e400003...` value handle `0x000f`; CCC descriptor `0x0010`.
- No motor telemetry was exposed through normal characteristic reads. Next useful step is protocol capture from the official app, or notification subscription plus known-safe query frames after framing/checksum are understood.
- Pulled CYC Ride Control APK from Android package `com.cyc.CYCRideControl`. The APK includes JSON telemetry layouts in `assets/flutter_assets/assets/json/`: `cyc_uart.json` is an 86-byte telemetry layout and `xSeries_uart.json` is a 156-byte extended layout.
- Android bugreport contained `btsnooz_hci.log`. It confirmed the app writes VESC `COMM_GET_VALUES` to NUS handle `0x000d` (`02 01 04...`) and receives notifications from handle `0x000f` beginning `02 57 04...`; `0x57` = 87-byte payload = command byte `0x04` plus the 86-byte `cyc_uart` telemetry block.
- Added `scripts/cyc_telemetry.py`, a read-only telemetry reader that sends VESC GET_VALUES (`02 01 04 40 84 03`), validates VESC CRC16, and decodes the APK-provided telemetry layouts.
- Fixed telemetry decoding to skip the leading VESC command byte before applying `cyc_uart.json`. Confirmed UI mapping: controller temp is `temp_fet_filtered` (26.5 C = 79.7 F), motor temp is `temp_motor_filtered` (23.5 C = 74.3 F), battery is `Input_V` (55.3 V), speed is `Speed` scaled by 100 and displayed as MPH when configured, `ODO=48` is kilometers and matches app display of about 30 miles after conversion.
